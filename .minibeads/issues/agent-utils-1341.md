# Description

[watermelon-full-preview] Research audit, delivered 2026-11-11 (owner replies 402 and 404). No product code changed. Owner questions: how much metadata does agentctl have/refresh for tracked agents? It knows their full CLI args — does it know their context-window percent, how many turns/tokens they have used, and any standard metadata about their output (deliverables such as diffs and PRs)? Plus from reply 404: is there any one-line description of what an agent is doing or is for (based on its original brief), and does it self-describe on any surface?

Findings, each measured read-only on real agents on one host (eight research lanes, an adversarial critic pass re-verifying on different files, one retained live status sample; full evidence report delivered to the requesting coordinator the same day):

- The registry record captures a launch completely (full post-program argv `subagents.rs:9620-9651`, record type `:1839-1931`, launch capture `:9833-9914`, replayable `launch_spec`) and nothing about consumption. The liaison's "no context/token/turn fields" is refuted literally (the record `token` is a generation id; status has an ephemeral screen-scraped Claude token counter `turn_state.rs:85-86,123-138`; headless turn events carry real per-turn usage including cost, never surfaced in status; Codex goals expose `tokensUsed`) but confirmed in substance: no window size, no context percent, no token accumulators, no cost, no turn counter in `agent.json` or interactive status. Refresh is event-driven only (start/anchor/move/rename/pause/goal/stop/revive/set); status and send never rewrite the record; the only quasi-periodic writers are per-spawn headless identity and one conditional watcher session-follow for Codex. watch-agents probes screens/processes/transcripts every 60 s for episode classification only (`agent_watch.rs`), and `!who` (chat bridge `chat_runtime/bang.rs`, not vibe-talk) re-reads records per answer and prints the stored lifecycle, not live state.
- Per harness, every wanted number exists in the harness's own transcript and current context is a tail read (milliseconds, size-independent); lifetime tokens and human turns are full-history reads. Claude: last-message logical input (native input plus both cache fields) is exact, but no window is stored anywhere on disk and observed occupancy (at least 572,912) refutes a 200k denominator; cumulative sums must dedup by message id (raw sums overcount 1.75–1.97x); stored cost snapshots are sparse and stale. Codex: rollout `token_count` carries last/total usage plus `model_context_window` (258400 on this host), so percent is derivable from a tail; turns are `task_started` events; no cost stored. Muse: last `model_completed` input tokens over the settings catalog limit (1000000) gives percent offline today, keyed by resolved model id; no cost or stored total. pi is installed but unknown to agentctl and left no session files on the audited host (all pi shapes docs-only).
- AgentCloud deliverables are journal-native and server-side, with no transcript scraping or workspace git inspection found: structured tool actions journal artifact registrations during execution (folded into session state), references (diff/task kinds) are journaled as discovered at run end, and people can register URLs by hand. Coverage is opportunistic (a minority of censused sessions), roster payloads carry no deliverables, and no pull-request or commit extraction was observed on any surface. For cloud-backed agents the two journal event types are directly reusable; for local harnesses nothing is — derivation is orchestrator-side. AgentCloud fleet rows do carry full token/context/occupancy data which agentctl's cloud status currently drops by allowlist (pinned by test). Locally, deliverables are derivable from live git (branch/HEAD, ahead/behind against a named remote-tracking landed ref, commit-body `#<number> <slug>` references, merge-base diffstat, patch-equivalence landed tests after replay landings) joined to slot records, with measured failure modes: recorded branch/head are creation snapshots, detached HEADs, nested worktrees invisible to a slots-only census, and no PR linkage recorded anywhere.
- Purpose (reply 404): `agent.json` has a `goal` field, null on 27 of 27 real records, and it is a delivered harness objective that prompts the agent (`subagents.rs` goal path) — not a description, and not safe to repurpose. Slots record a one-line purpose that nothing displays; briefs are never distilled; no surface self-describes an agent. The existing `--purpose` start flag is agentcloud-provision-only. Security note for every future surface: raw `agentctl status` embeds the full record including generation tokens and arguments — render allowlisted fields only, never forward raw status.

# Design

Enriched `!who`/status (bulleted Markdown in the #1339 bang-answer-markdown shape) and build plan, cheapest first. Rules: derivations stay ephemeral or watcher-cached with printed age, never timer-written into `agent.json`; unknown prints `?` with a reason, never a neighbouring metric; roster stays terse, detail (`!who NAME`) carries context/turns/tokens/purpose/slot-branch/deliverables; one-line status over additive ephemeral `usage{}`/`git{}` JSON.

- #1342 agent-purpose-line (builds first, its own issue): display-only `purpose` extension key (distinct from `goal`, coordinator-approved), sourced at start from a generalized `--purpose`, else the slot's wrkslots purpose, else the brief's first meaningful line (model summary later, never blocking); `agentctl purpose` command modelled on `agentctl set`; shown in status/list, !who detail (after #1339), and the console banner; tab title is a separate careful step because tab label equals agent name in identity proofs today.
- bang-answer-markdown (#1339, in flight): bulleted roster/detail rendering. Read cost unchanged.
- cloud-fleet-tokens: widen the cloud status allowlist to surface already-fetched fleet occupancy/cumulatives, percent `?` until the window-versus-budget semantics are answered upstream. Read cost zero.
- who-registry-fields: render already-read record fields (slot, profile, effort) and prefer #1340 agent-model-unknown's `resolved_model`. Zero new I/O (`bang.rs` only).
- harness-tail-usage: extend #1340's `transcript_model`/`capture_resolved_model` seam (file located via `adapter.transcript_path`, head capture unchanged) with a tail-window usage reader per harness — Muse and Codex percent, Claude occupancy-only — surfaced as ephemeral status `usage{}`. Read cost: one bounded tail per agent (5 ms class, size-independent).
- claude-context-window-table: checked-in window table keyed by resolved model id, with a registry-configuration override; a model id carrying a 1M-context marker resolves to 1,000,000 before the table. Initial entries must be proven per model (one `/context` observation or service-catalog read, source recorded; the audit's occupancy floor is a sanity bound, not a value). Stays current: a test fails when a configured profile model lacks an entry; readers cross-check occupancy/compaction values and degrade loudly (`window_source: stale-table`, percent `?`) instead of printing a computed >100% as fact.
- who-usage-detail: `!who NAME` performs one tail read. Roster unchanged.
- turn-token-index: human turns and lifetime tokens via an incremental (inode, offset, recent-ids) index (the `rs/agent-usage` pattern), definitions per harness (Claude distinct prompt ids with message-id dedup, Codex task starts, Muse user intents), labelled for fork baselines and elided history. Lazy/detail-only; first pass is the expensive one.
- slot-git-derivation: batch worktree enumeration, left-join to slot records, minimal live git per slot against a named landed ref, patch-equivalence landed test on detail only. Roughly 150–200 ms per slot.
- cloud-deliverables-fold: detail view folding the two inert journal queries for cloud agents. Blocked on upstream answers (derivation inputs/kinds, registration rules, hosted coverage, supported read surface); never promise PR/commit extraction.
- watch-metadata-cache: the 60 s watcher pass maintains tail-usage and git-lite cache records with computed-at stamps; roster/list read only the cache and print its age. Depends on the tail and git steps.

Non-goals: no record schema change, no pane-footer scraping for percents, no cost until a provenance-labelled price table is approved, no pi support until a real session file exists on a host to read.

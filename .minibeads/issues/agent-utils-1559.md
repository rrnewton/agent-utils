# Description

[watermelon-full-preview] Owner 081 asked for recovery with less fragile deterministic code and more agent judgement; the lead-approved design is the harness living plan `ai_docs/plans/2026-11-15-restore-recovery-agent-plan.md` (harness repo), building on `ai_docs/plans/2026-11-12-team-restore-protocol.md`. Owner corrections on 2026-11-20 reshaped the agent half: 234 (recovery watches from the start), 235 (one-shot calls in a loop, muse first then claude then codex, "emergency recovery mode"), 242-244 (coordb's harness-local shepherd-v0; the shepherd always starts at boot from its own minimal unit, in parallel with restore, monitoring it), 245 (lane restore is both jobs idempotently; lanes may return before the lead; the coordinator sweeps), 243 (per-team YES = lead running + bridge healthy + handoff acked), 256 (restore stays outside Herdr; a `system > recovery` tab tails the recovery log), 257 (report records missing profile/bypass/effort/session; never rewrite them). Phase plan approved by coordb 2026-11-20: judgement-only one-shots, effects only via `team act`; Rust `team shepherd` loop + standalone wrapper script; no bind/record-repair in boot recovery; bounds 300 s per call, 20 rounds / 120 min, early escalation on two identical no-progress snapshots (configurable).

# Design

- Phase 1 (deterministic half, no agent yet): freeze `agentctl-team-manifest/v1` as a redacted allowlist projection of the status rows DETECT already computes — never raw records (record tokens must not reach an agent brief) — with `record_gaps` (missing profile/bypass/effort/session, ambiguous candidates with first-prompt evidence), queued census, unit booleans, refusals, `lost[]`, `errors[]`, and the embedded `agentctl-team-verify/v1` result. Then `agentctl team act --incident I --request-id R <action>`: validated against the manifest, idempotent per request-id, persisted in the driver record, verify-after, exits 0/75/1. Allowlist v1: facts, revive (recorded session only), start-unit/reset-unit, drain, kill-pid, bridge gap actions wrapping the landed pin-guarded gap verbs, declare-done (a full-VERIFY request), escalate. No `bind-session` and no record-repair writes anywhere in boot recovery (257); candidates are report-only. New persisted data (DriverRecord `manifest`/`actions[]`, shepherd stamp/state files) is reported to coordb before each landing because another team pins an older agentctl reader.
- Phase 2 (shepherd): a standalone `run-agent-prompt` wrapper tries `muse exec`, then `claude -p`, then `codex exec` (stateless, tool-less, hard process-group timeout, distinct all-fail exit 69, logs which harness answered). The shepherd loop starts unconditionally at boot from its own minimal unit in parallel with restore (no ordering on restore or Herdr), polls manifest/verify facts for every team in the restore-teams teams config, and per round accepts at most one own-team `team act` proposal from the one-shot's structured final JSON line. It finishes only on a deterministic YES per team — lead running, bridge healthy, handoff acked, each an explicit pass (held/skipped never count) — including other teams' leads judged read-only, or on bounded give-up with escalation + stamp. If deterministic checks pass with all harnesses down, the stamp still says YES with judge=none. The shepherd unit appears in `services list` and turnover like other agent-utils daemons; watch/turnover defer while an incident is non-HEALTHY. Visibility: per-boot recovery log under `~/.local/state/agentctl/shepherd/<boot-id>/`, best-effort `system > recovery` Herdr tab tailing it (display only).
- Split: #1975 (slot re-attach, sweep-notice wording, longer boot-restore timeout) and #2000 belong to mu-restoreboot; #1934/#1992/#1993 belong to mu-restorefix. This lane consumes their landed outputs and reports absent state; it does not duplicate them.

# Acceptance Criteria

- A human driving `team act` by hand recovers a scratch drill team end to end; duplicate request-id and stale incident are safe refusals/no-ops; held/skipped verify rows can never produce YES.
- Scratch-registry drill with a fake Herdr (`--herdr-bin`) and fake muse/claude/codex executables proves shepherd fallback order, timeout fall-through, deterministic YES/NO, cross-team read-only judging, and record-gap reporting — without a real reboot, restore, or live registry.
- Wrong-conversation safety: ambiguous or missing native sessions refuse with named candidates in both Rust and Python editions (where mu-restorefix has not already landed it); restore/recovery rewrite no records.
- Every liveness/restore/revive change gets a coordb cold review before gating; landings only on coordb LAND NOW; no real restore/reboot drill without coordb's explicit OK.

Phase 2 design check (mu-shepherd, 2026-11-22; no code yet, awaiting coordb go):

- Watches: for every team in the restore-teams teams config, one shared probe pass per round — `team manifest` (the landed `agentctl-team-manifest/v1`: desired set, allowlist agent rows, `record_gaps`, queued census, unit booleans, `lost[]`, `errors[]`, embedded verify) — plus this epoch's restore report and the driver record's `state`/`incident`. The harness-local shepherd-v0 free-text facts file is superseded by the manifest; raw records never reach a brief.
- When it acts: one incident per restore epoch (kernel boot plus user-manager identity, the same epoch the restore replay guard uses). The boot unit starts it unconditionally; inside the incident it loops rounds (one `run-agent-prompt` one-shot per round) until deterministic YES or bounded give-up. It is not a perpetual death watcher: a mid-session death stays with watch / `team kick` / the driver, and the shepherd re-enters only on a new epoch or an explicit manual `team shepherd` run, which resumes or no-ops against the existing stamp. This settles "one shot per boot or per detected death" as one incident per boot epoch, many bounded rounds inside it.
- What it runs, in order per team: (0) the two-restorer probe below; (1) `agentctl restore --dry-run`, read before anything runs (`desired_state_source` must be registry-derived; `refused` read now); (2) real `agentctl restore` only when the dry run shows desired agents down and no restore has completed this epoch; `--force` only in the skill's replayed-but-visibly-down case (dry run says `already-restored`/`replayed: true`, agents visibly down, as after a user-manager restart) — `--force` bypasses only the replay, never a refusal; (3) the judgement loop: the brief is the manifest, the one-shot's structured final JSON line carries at most one proposal, and the only effect path is `agentctl team act --incident I --request-id shepherd-<epoch>-r<round> <action>`, validated by the driver against a fresh manifest, idempotent per request-id, verify-after. No `bind-session`, no record repair, no raw signals; `kill-pid` only through the landed guarded verb. Open for coordb: whether step (2) should instead be `team kick` (whose driver already detects/restores/verifies) — this note recommends plain restore for steps (1)–(2) so the shepherd's deterministic arm stays exactly the skill protocol a human would run, with the driver owning only `team act` effects.
- Two restorers (team-restore skill step 0, mechanised): if the team's lead answers (`agentctl send` probe / lead live in the manifest), the shepherd judges that team read-only and never acts; an active boot restore unit, a this-epoch restore report still being written, or freshly moved state directories (for example `bridge.old-*`) mean defer and re-probe next round; the per-team driver state flock is held for any round that may act, so a second shepherd or driver invocation only reports state; `restore`'s own replay guard is the second layer underneath. Cross-team rule from the phase plan stands: act only on an own team (no live lead, step 0 clear), judge every other team read-only in the same stamp.
- How it reports: per-boot directory `~/.local/state/agentctl/shepherd/<boot-id>/` with the round log, the last manifest per team, and a terminal stamp; the stamp is also queued to each acting team's lead with `agentctl send` (queued, never blocking), and give-up escalates through the landed escalation path plus the stamp. The unit appears in `services list` and turnover like other agent-utils daemons; watch/turnover defer while an incident is non-HEALTHY. A best-effort `system > recovery` Herdr tab may tail the log, display only; restore stays outside Herdr. YES is deterministic only: lead running, bridge healthy, handoff acked, each an explicit pass — held/skipped never count — and if every harness is down while the checks pass, the stamp still says YES with `judge=none`.
- Boot unit: a new minimal `agentctl-shepherd.service` rendered by `agentctl install-units` (a `--shepherd` spelling beside `--teams-config`, exact flag for coordb to confirm), `Type=oneshot`, no `After=`/`Requires=`/`BindsTo=` on restore or Herdr (it starts in parallel and monitors restore; restore never waits for it), timeout covering the 120-minute bound. `install-units` writes the file only and never enables, starts or reloads anything; the operator enables it deliberately, as with the tab-hygiene timer.
- Persisted fields (reported before landing, per the older-reader rule): no `DriverRecord` change is proposed — the loop reuses landed `manifest`/`actions[]`. New files live only under the shepherd state directory: `stamp.json` (proposed schema `agentctl-team-shepherd-stamp/v1`: `boot_id`, `epoch`, `incident`, `registry` key, `verdict` YES/NO/GAVE-UP, `judge` muse/claude/codex/none, `rounds`, `started_at`/`finished_at`, per-team check booleans, `record_gaps` count) and a resumable `state.json` (`round`, last manifest hash, consecutive no-progress count). Both are new paths no older reader opens, so a pinned older agentctl is unaffected; any later addition stays additive within v1.
- Scratch drill (the acceptance test, never a real team): a Rust integration test over a scratch registry and state root, fake Herdr via `--herdr-bin`, fake `muse`/`claude`/`codex` executables on the generated-fake pattern of `py/tests/test_run_agent_prompt.py`. It proves fallback order and timeout fall-through, the dry-run → real → `--force`-after-user-manager-restart sequence, one act per round, duplicate request-id and stale incident as safe refusals, step 0 (a live lead makes the team read-only), deterministic YES/NO and bounded give-up with early escalation after two identical no-progress snapshots, cross-team read-only judging, record-gap reporting, and `judge=none` YES — with no real reboot, restore, pane, unit or live registry.
- Bounds as approved: 300 s per one-shot call, 20 rounds / 120 min per incident, configurable early escalation on two identical no-progress snapshots. Landing 2b (bridge gap actions) stays out of the shepherd loop unless coordb says otherwise at this check.

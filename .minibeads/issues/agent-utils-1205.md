# Description

Owner request (2026-11-10): lanes run in their own mount namespace but every mount is rw, including the whole project and /data. Restore the intended boundary: a lane may write only its slot, its experiments directory, ai_docs/, a per-project tmp (below), and harness state (agentctl registry/queue, herdr sockets, harness tool caches, session state for each harness, cargo/npm caches if needed). Everything else read-only. Add a per-project tmp inside the worktree image with a declared TTL (72 h proposed, not yet owner-confirmed) and deterministic reaper cleanup, writable by the lane. Add a soft 2 GB guideline per experiments subdirectory: over it, the lane justifies the size in its status file. Draft a temp-data skill (extract results/notes from tmp into experiments before reclaim); skill text needs owner OK before landing. Phase 1 is survey and design only; no enforcement on live lanes, no harness profile changes, trials only in scratch.

# Design

SURVEY (2026-11-10, this lane, read-only). (1) The box already exists: py/wrkslots/sandbox.py build_view makes /tmp a fresh 16G tmpfs, HOME read-only with home_shared bound rw (.claude, .codex, .muse, .config/muse, .local/share/muse, .local/state/herdr, .cargo/registry, .cargo/git), home_private per-slot (.cache, .buck), home_hidden masked, slot+git-dirs+outputs(ai_docs, experiments)+read_write writable, and with protect_system=true every other mount remounted read-only per-mount via MS_BIND|MS_REMOUNT|MS_RDONLY preserving locked flags (sandbox.py _remount_tree_read_only). Config today: isolation=root, protect_system=true, outputs=[ai_docs, experiments], tmp_size=16G (wrkslots sandbox show-config). wrkslots run/shell-command/box all build this view; image and plain slots identical. (2) Why live lanes are all-rw: agentctl start boxes only with explicit --slot/--project-box; profiles.json defines no slot/box for any profile, and Muse lanes are launched with --cwd SLOT only. This lane proves it: own mount ns differs from host, yet 627 rw vs 6 ro mounts, harness started with sandbox disabled. Root isolation in agentctl supports claude and codex only (sudo terminal relay), so Muse cannot take the root path today; userns/cgroup are the only Muse-compatible modes, and cgroup has no filesystem view at all. Fix direction: make agentctl apply the wrkslots view for every harness (userns for Muse unless its launcher needs setuid, then solve the relay), default on via profile flag. (3) Harness write needs already covered by home_shared/home_private above; npm cache lands in per-slot .cache, cargo target dirs are inside the slot (cache_globs rs/target), cargo registry/git shared rw. Missing from the writable set: gate admission state /tmp/dev-agent-utils-gate-admission (must be read_write or gates queue outside the box), herdr-run (runs outside the box by design on the host pane; its .herdr-run audit spool is project-local and must stay host-side), agentctl registry (coordinator box writable exception already; slot box keeps control dir read-only so heartbeat runs outside). (4) Recursive RO: kernel 7.1.3 supports mount_setattr with AT_RECURSIVE (one call vs ~310 remounts), but the existing per-mount loop already works unprivileged (verified in scratch: unshare userns bind+remount ro gives EROFS) and preserves locked nosuid/nodev/noexec flags; recommend keeping the loop, optional mount_setattr fast path with fallback. No denied-write logging exists today: a denied write is a silent EROFS. DESIGN. (a) Writable-set declaration stays in wrkslots config sandbox section (per project, .wrkslots.yml), extended with lane_tmp {relpath: tmp, ttl_hours: 72} and experiments {soft_limit_gib: 2}; agentctl reads the same config, no second list. (b) agentctl start applies the view for claude, codex and Muse alike; --slot-isolation gains a Muse-usable path. (c) Per-project tmp: project-root tmp/ inside the slot image, created at provision, reaper (wrkslots subcommand on the coordinator tick) deletes entries older than TTL by mtime, logs each deletion, never follows symlinks out; lane sees it writable via outputs/read_write binding. TTL 72 h pending owner confirmation. (d) Experiments guideline: wrkslots audit reports any experiments subdir over 2 GB as a warning; lane records justification in its status file; no deletion. (e) Denied-write logging: trial phase records EROFS via a fanotify/audit watch on protected mounts into the slot state log so missing writable paths are learned before default-on; ship log-only first. (f) Rollout: opt-in profile flag, one trial lane, then default; live lanes and profiles.json untouched in Phase 1. (g) Temp-data skill drafted for owner review (scratch/staging only, not landed): before tmp reclaim and at task end, copy results, tables and notes worth keeping into experiments/<task>/ with a README stating source tmp path, date and repro command; verify checksums; never move secrets or caches.

# Notes

## Phase 2 (agentctl side, opt-in)

Implemented behind profile flag `write_sandbox` (default off; no live lane enabled): profiles accept `write_sandbox`/`slot_isolation`; a start with such a profile and `--cwd` inside `worktrees/slots/<name>` boxes to that slot for claude, codex and Muse; a `root` project isolation coerces to `userns` for Muse (explicit root still refused). wrkslots binds the gate-admission directory writable when $GATE_ADMISSION_DIR is explicitly exported and exists, and $WRKSLOTS_DENY_LOG=1 wraps the boxed command in strace failed-file-syscall logging (log-only, no strace = untraced). Per-project tmp TTL/reaper, the 2 GB guideline and the trial lane wait for owner-confirmed figures.

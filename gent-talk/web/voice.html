        Control bar

        The strip carrying the gear and the Voice/Discord switch. It can sit under the title at the top of the screen, or in the dock directly above the big buttons — bottom is the default, because that is where your thumb already is and because the header then costs no row at all. The gear is deliberately at the far left of it: it is the control you least want to hit by accident.

        Canned prompts

A button that claimed that scoping would produce confident, wrong summaries. See ai_docs/UNREAD_STATUS_20260819.md.

        What the controls do

        Mute keeps the call open and keeps the agent's context; it only stops sending it your audio. Your phone will still show the microphone as in use, because the microphone really is still open — which is what lets unmuting drop you back into the same conversation rather than a new one. Hang up ends the conversation. The vendor cannot resume a call once it has closed, so the next call is always a new one; the lines already on screen stay there because they are still your own record of what was said, and the transcript marks where one conversation ended and the next began. With Resuming below turned on, this server reads the earlier lines back to the new call so it can carry on from them — that is a reconstruction from our side, not the same conversation, and the transcript seam says which of the two you got. Sound silences the agent's voice without silencing the agent: its replies keep arriving as text in the transcript. It keeps receiving that audio and throws it away rather than asking for a text-only conversation, because the response format is settled once when the conversation opens — switching it would mean closing and reopening the socket, and a reopened socket is a new conversation that remembers nothing. Silencing the agent must not cost you its memory. Type turns the control bar into a text box that sends what you write into the same conversation you are speaking in, so a typed turn and a spoken one land in the same transcript and the agent answers either one out loud. It is a toggle: the same button leaves text entry again, and whatever you had half-written is still there when you come back to it. Clear empties this screen only and never makes the agent forget anything. It asks twice, because it sits under your thumb and it cannot be undone. It also leaves the stored record on the server untouched, so the conversation comes back the next time you sign in — Forget stored conversations, below, is the only control that erases that, and it leaves the screen alone in return.

        The channel

        The Discord view shows the channel as Discord holds it, rendered from a small, fixed markdown subset. Message text is written by other people and bots: it is escaped before anything else happens and is never treated as markup or as an instruction. Every line shows its author and its message id, so a message the agent describes can be checked against a real one — or shown not to exist.

        Reading width

        On a wide screen with a mouse, the transcript and the channel are held to a column rather than filling the window: a line of text stops being readable somewhere past ninety characters, and a maximised browser is twice that. Drag the edge of the column, or use this — they set the same thing. On a phone it does nothing, because there is no room for a column and no margin to put beside it.

        Resuming

        The vendor cannot resume a conversation once the connection closes. What this does instead is hand the new call a written record of the earlier one, so it can carry on from it. It is a reconstruction: a new conversation that has been told what happened, not the old one continued.

        It re-sends earlier conversation content to the voice vendor on every new call — your own speech, and any Discord text the agent read out to you, which was written by other people. That is why it is off by default. The record is capped by the server; when it does not all fit, the oldest lines are dropped and both you and the agent are told the reconstruction is partial.

        Live messages

        When this server is set to watch the channel, new messages appear here on their own rather than at the next refresh. It is a poll, not a push from Discord: the newest message can be up to one interval old, and the interval is set on the server.

        While a call is live, each arriving channel message is sent to the agent as background information, so it can mention a reply that lands mid-conversation instead of waiting to be asked. This sends channel text to the voice vendor and it costs conversation time, so it is off by default. Replies this server posted are never sent back — otherwise the agent would hear its own answer and reply to it.

        It only works while this page is open. The conversation socket belongs to this browser, not to the server, so closing the tab ends the relay even though the server keeps watching the channel.

        Only messages that arrive while the feed is connected are sent. When this page attaches to the channel it is first handed what the server already published, so the list catches up; that catch-up is never announced to the agent, because a burst of older messages read out as though they had just been said is worse than not hearing them at all. Anything that landed while the feed was reconnecting is on screen but was not spoken.

        Stored conversations

        This server keeps the transcript of each call in a database file on the machine it runs on, so a reload no longer loses the conversation. It is not encrypted: anyone with access to that machine's filesystem can read it, and it holds both your own speech and any channel text the assistant read out to you. Older conversations are dropped automatically once the server's retention limit is reached.

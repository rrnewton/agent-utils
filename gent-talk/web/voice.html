        What the controls do

        Mute keeps the call open and keeps the agent's context; it only stops sending it your audio. Your phone will still show the microphone as in use, because the microphone really is still open — which is what lets unmuting drop you back into the same conversation rather than a new one. Muting and unmuting each send the agent a note saying the pause is deliberate, because withholding your audio looks to it exactly like you going quiet, and that is what makes it start asking whether you are still there. Whether it honours that note has not been tested against the live service yet. The call is billed while muted either way: what is metered is the conversation being open. Hang up ends the conversation. The vendor cannot resume a call once it has closed, so the next call is always a new one; the lines already on screen stay there because they are still your own record of what was said, and the transcript marks where one conversation ended and the next began. With Resuming turned on, this server reads the earlier lines back to the new call so it can carry on from them — that is a reconstruction from our side, not the same conversation, and the transcript seam says which of the two you got. Sound silences the agent's voice without silencing the agent: its replies keep arriving as text in the transcript. It keeps receiving that audio and throws it away rather than asking for a text-only conversation, because the response format is settled once when the conversation opens — switching it would mean closing and reopening the socket, and a reopened socket is a new conversation that remembers nothing. Silencing the agent must not cost you its memory. Type turns the control bar into a text box. During a call it sends what you write into the same conversation you are speaking in, so a typed turn and a spoken one land in the same transcript and the agent answers either one out loud. Pressed with nothing open it starts a typed conversation instead: the microphone is never requested, so there is no permission prompt and no in-use indicator, and there is no Talk or Sound button because there is no microphone to mute and no voice to silence. That is a different kind of conversation, chosen when it opens — not a call with two switches thrown, which is what it used to take. This page also asks the agent for a text-only response, but that is an override an agent's own settings can refuse; if it is refused the agent's audio is received and thrown away, the connection details say so, and nothing about the microphone changes. It is a toggle either way: the same button leaves text entry again, and whatever you had half-written is still there when you come back to it. Clear empties this screen only and never makes the agent forget anything. It asks twice, because it sits under your thumb and it cannot be undone. It also leaves the stored record on the server untouched, so the conversation comes back the next time you sign in — Forget stored conversations is the only control that erases that, and it leaves the screen alone in return.

        Microphone

        These are asked of the browser when the microphone opens, so a change applies to your next call, not the one in progress.

        Echo cancellation stops the agent hearing itself through your speaker and answering its own voice. Headphones solve this too; leave it on if you are on speakerphone.

        Noise suppression filters steady background noise — a fan, road noise, a room's hum.

        Automatic gain control amplifies quiet input. In a near-silent room it boosts small incidental sounds — a phone being set down — until they cross the speech threshold and get transcribed as words. Turn it off if you are getting phantom transcripts.

        Control bar

        The strip carrying the gear and the Voice/Discord switch. It can sit under the title at the top of the screen, or in the dock directly above the big buttons — bottom is the default, because that is where your thumb already is and because the header then costs no row at all. The gear is deliberately at the far left of it: it is the control you least want to hit by accident.

        Canned prompts

        What the two prompt buttons in the control bar say. They send exactly this text into the live conversation, as though you had typed it. Emptying a field puts its default back rather than leaving a button that does nothing. Both are greyed out when there is no call, because there is nothing for the sentence to reach.

        Sumry deliberately says recent messages and not "my unread messages since I last spoke". Discord gives a bot no read state at all, and this bridge cannot work out where you last spoke either — your own replies are posted as the bot, and the only author signal is a display name anyone can set to anything. A button that claimed that scoping would produce confident, wrong summaries. See ai_docs/UNREAD_STATUS_20260819.md.

        Blockers makes the coding agent do work. It is not a question about the channel; it asks the voice agent to go and get the coding agent to report. It is drawn as an ordinary button rather than a warning: the cost is real, but a control that looks like a fault report is worse than one whose cost is stated here.

        Who is who in the channel

        The call transcript tells its two speakers apart by side, colour and corner. The channel can do the same, but only once it knows which account is which — Discord offers no such thing, and a display name is chosen by whoever owns the account. Everyone who has spoken in a channel you have opened is listed, with what this page guessed shown in italics; change any of them and the channel is redrawn.

        The guesses, in the order they are tried: the account this bridge posts as is you — your own replies and anything your voice bot says go out through it, so they are your words even though a bot delivered them; a lone bot that is not this bridge is the coding agent; everyone else is another person or another bot. With two candidate bots the guess refuses rather than picking one. Nothing here is sent anywhere: it is stored in this browser and affects only how the channel is drawn.

        The channel, and the inbox

        The Discord view shows the channel as Discord holds it, rendered from a small, fixed markdown subset. Message text is written by other people and bots: it is escaped before anything else happens and is never treated as markup or as an instruction. Every line shows its author and its message id, so a message the agent describes can be checked against a real one — or shown not to exist.

        A message somebody has answered is dimmed. That is derived from the channel itself — Discord records a reply only on the answering message — so it can only see answers that are loaded: a reply further back than you have walked is invisible, and a message can be dimmed later than it should have been, never earlier.

        Archive is your own judgement, and it is recorded on the server — so it survives a different browser, a different device and a cleared cache. Swipe a row on a touch screen, or use the row's button on any device; swiping an archived row puts it back. By default an archived row stays where it is, greyed and drained of colour, so you can see what you have dealt with and change your mind. Hide archived takes them out of the list entirely, which is what turns the channel from a log into a queue.

        Your own messages

        A message posted on your behalf is one you dictated moments earlier, so it is already read by the only definition that matters. Leaving it in the queue would make the queue partly a record of things you said rather than things waiting for you.

        With this on they are greyed in the channel and left out of the list behind Hide archived. It is not an archive: nothing is recorded on the server, there is nothing to undo, and turning it off brings every one of them straight back. Nothing here changes anything in Discord.

        What to call a channel

        Give a channel a name of your own. This app then uses it everywhere it would have shown the configured label — the picker, the channel summary, and the name the voice agent is given, so what you say out loud is what it was told.

        It is ours and local: it is kept on this server, Discord is never told, the channel is not renamed there, and nobody outside this deployment sees it — the same standing as which messages you have dealt with. Clearing it puts the configured label back.

        It is also not something the agent can set. The agent is given the name and cannot choose it, because a model that renames the channels it also reports on can make its own reports unrecognisable.

        Reading width

        On a wide screen with a mouse, the transcript and the channel are held to a column rather than filling the window: a line of text stops being readable somewhere past ninety characters, and a maximised browser is twice that. Drag the edge of the column, or use the slider — they set the same thing. On a phone it does nothing, because there is no room for a column and no margin to put beside it.

        Resuming

        The vendor cannot resume a conversation once the connection closes. What this does instead is hand the new call a written record of the earlier one, so it can carry on from it. It is a reconstruction: a new conversation that has been told what happened, not the old one continued.

        It re-sends earlier conversation content to the voice vendor on every new call — your own speech, and any Discord text the agent read out to you, which was written by other people. That is why it is off by default. The record is capped by the server; when it does not all fit, the oldest lines are dropped and both you and the agent are told the reconstruction is partial.

        Live messages

        When this server is set to watch the channel, new messages appear on their own rather than at the next refresh. It is a poll, not a push from Discord: the newest message can be up to one interval old, and the interval is set on the server.

        Telling the agent about arriving messages sends each one into a live call as background information, so it can mention a reply that lands mid-conversation instead of waiting to be asked. This sends channel text to the voice vendor and it costs conversation time, so it is off by default. Replies this server posted are never sent back — otherwise the agent would hear its own answer and reply to it.

        It only works while this page is open. The conversation socket belongs to this browser, not to the server, so closing the tab ends the relay even though the server keeps watching the channel.

        Only messages that arrive while the feed is connected are sent. When this page attaches to the channel it is first handed what the server already published, so the list catches up; that catch-up is never announced to the agent, because a burst of older messages read out as though they had just been said is worse than not hearing them at all. Anything that landed while the feed was reconnecting is on screen but was not spoken.

        Stored conversations

        This server keeps the transcript of each call in a database file on the machine it runs on, so a reload no longer loses the conversation. It is not encrypted: anyone with access to that machine's filesystem can read it, and it holds both your own speech and any channel text the assistant read out to you. Older conversations are dropped automatically once the server's retention limit is reached.

        Connection status

        What the current conversation is, what audio format it negotiated, and why the last one closed — including the close code, which is the one thing on this page written for whoever is debugging it rather than for you. It is a readout, not a setting, which is why it sits at the end.

        Unset, a message is read at whatever pace the voice agent is configured with.

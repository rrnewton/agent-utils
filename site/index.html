agent-utils

Built for those who like agents both in Herdr/tmux and over chat, and who want multi-harness, multi-model agent orchestration, but without an all-or-nothing, batteries-included platform.

Instead, in the Unix tradition, agent-utils is a collection of small, composable a la carte tools. It's a deconstructed Gas Town/City. These tools solve the individual problems of long-term agent management across multiple machines: inter-agent/inter-harness communication, recovering after reboot, managing ornery TUIs as well as headless agents, optional issue tracking, an optional merge queue, and so on.

There's even an improved Slack/Discord client optimized for vibe-coding!

Get started How it works Source
  • Free, MIT-licensed, runs on your own Linux machine
  • Drives the agent CLIs you already use, such as Claude Code and Codex
  • Needs Herdr, a terminal server; pre-1.0

How it compares

Gas Town bundles a coordinator, worker roles, persistent work tracking and a merge queue. Gas City runs tasks through formulas for implementation and review, with a dashboard to follow progress. Both offer an integrated workflow for a team of agents.

Claude Squad manages agents in tmux sessions and separate Git worktrees from a terminal dashboard. Happy provides mobile and web control of Claude Code and Codex through a synchronization server.

agent-utils lets you assemble the workflow. Use agentctl for named sessions and messages, wrkslots for worktrees, and your choice of tracker and landing process. Add chat, phone access or a merge queue as needed. Your coordinator is an ordinary coding agent following your project's instructions.

Why

What it solves

Running agents for days across several machines makes sessions, messages and unfinished work harder to track.

Agents trip over each other

Two agents in one checkout overwrite each other's work, and one runaway build can fill the disk.

wrkslots gives each agent its own Git worktree and branch, with resource limits and, optionally, its own disk image.

Prompts get lost or sent twice

A follow-up typed into the wrong terminal, or resent after an unclear failure, is hard to undo.

agentctl queues prompts, checks delivery to the right agent, and sets uncertain deliveries aside for inspection.

Background agents are a black box

You cannot steer an agent you cannot see.

Attach to interactive agents in Herdr or tmux; manage headless workers with the same agentctl commands.

A reboot takes the team down

After a restart, every agent, tab and chat bridge is gone.

agentctl restore restarts agents from saved launch settings, then starts the configured bridges and services.

Cleanup destroys work

Deleting a worktree that a process still uses, or that holds unpushed commits, loses work.

wrkslots deletes a slot only when nothing uses it, and saves unpushed commits first.

Agents claim success too early

A subagent's "tests pass" may cover the wrong tests, or none.

The coordinator reads the diff and the test output itself before it lands anything.

You are away from the terminal

Questions pile up while you are in a meeting or on your phone.

agentctl chat connects the coordinator to a Slack or Google Chat channel, and vibe-talk is a phone client built for agent chat.

Teams on other machines cannot talk

A coordinator on one host has no reliable way to reach one on another.

agent-teams routes messages between team coordinators and prevents duplicate delivery.

A sandbox blocks the last step

A sandboxed agent can finish the work and still be unable to push it.

herdr-run runs your allowlisted commands, such as git push, in a visible pane outside the sandbox.

Merges break the main branch

Changes that pass on their own can fail together, and landing them one at a time is slow.

merge-queue batches ready changes by their real conflicts, tests each combined tree, and lands only what is green.

Shared limits run out quietly

Agents share one machine's CPUs and memory, and often one GitHub account.

dagrun caps validation's CPU and memory, gh-paced paces GitHub calls, and agent-usage shows plan usage.

Tasks get dropped

Work handed out in chat has no queue, and nothing is closed when it lands.

minibeads keeps tasks as Markdown files in the repository, with claims and dependencies. Any other tracker works too.

Architecture

How it fits together

One coordinator delegates work to agents in separate worktrees. A project that adopts the suite gets a harness: a folder that holds your checkout, the tools and the instructions they share.

The architecture page covers each layer, one task from start to finish, and where state lives.

Tools

The tools

Setup includes agentctl and wrkslots. Add chat and other tools as you need them, or use any tool on its own.

Core

agentctl corebeta

Start, message, read and stop coding agents by name, from your shell, a script or the coordinator. Prompts are saved before delivery; uncertain sends wait for inspection.

User guide for agentctl

wrkslots core

One Git worktree slot per agent, with ownership records and handoffs. A slot is removed only when nothing uses it.

README for wrkslots

agentctl chat coreconnect later

Connects a Slack or Google Chat channel to the coordinator: your messages go into its pane, and its replies come back to the thread.

Chat quickstart for agentctl chat

Herdr external

A persistent terminal server for interactive agents, with tabs you can attach to and use yourself. Installed separately.

Upstream project: Herdr

Optional

herdr-run optional

Runs an allowlisted command, such as git push, in a visible Herdr pane outside the agent's sandbox, and logs every run.

Quickstart for herdr-run

tick-hub optional

One timer checks many recurring duties, each on its own cadence, and sends whatever needs action to the coordinator.

README for tick-hub

dagrun optional

Runs validation as a dependency graph under CPU, memory and named-resource limits. This repository validates itself with it.

README for dagrun

agent-teams optionalbuild from source

Routes messages between team coordinators on one machine or several, with duplicate prevention.

Quickstart for agent-teams

merge-queue experimental

A local merge queue: it orders ready changes by priority and real conflicts, tests each batch's combined tree, and lands only green batches.

Quickstart for merge-queue

wrkviz optional

A zoomable timeline of what the coordinator and its subagents did, built from their transcripts.

README for wrkviz

gh-paced optionalbuild from source

Paces gh calls to reduce rate-limit errors when agents share a GitHub account.

Shows Claude Code and Codex plan usage, reset times and burn rates without a model call.

minibeads optionalsubmodule

An issue tracker that keeps each issue as a Markdown file in the repository. A separate project; other trackers work too.

vibe-talk optionalearly

A phone and desktop client for agent chat on Slack or Discord: summaries, named threads, triage, Discuss and read-aloud. Deployed separately.

An advisory plan for landing a queue of pull requests, from real merge conflicts and CI state. It never changes a pull request.

Adopt it

Adopt it for a project

Start in your project's checkout. The setup skill checks the machine, walks you through the choices and asks you to approve the changes.

  1. Tell your agent

    Adopt agent-utils for this project, following skills/agent-utils-setup/SKILL.md from https://github.com/rrnewton/agent-utils.

    Say it to Claude Code, Codex or another supported agent CLI.

  2. It detects

    It checks your Git layout, installed agent CLIs and the dependencies needed to run them in separate worktrees.

  3. It asks

    Choose agents and launch profiles, worktree storage and limits, build caches, and whether to connect chat. Each question has a default.

  4. It shows the plan, then acts

    Review the proposed folders, files and installs, then approve the setup.

  5. It checks and hands over

    It checks the tools, offers a trial task, then starts your coordinator.

What you end up with

~/work/foobar/             the harness; the coordinator runs here
  AGENTS.md                makes the agent here the coordinator
  foobar/                  your checkout, moved in unchanged
  agent-utils/             tools in bin/, skills in skills/
  worktrees/               wrkslots: slots and their registry
  bin/agent-liveness       has a slot's agent stopped?
  .agents/skills/          links to the suite skills
  .claude/skills -> ../.agents/skills
  .agentctl/profiles.json  launch profiles; private
  .wrkslots.yml            slot policy, commented

The harness has its own Git history; your checkout keeps its existing history inside it. Tools run from the agent-utils checkout, with Rust tools built on first use. Later, ask the coordinator to "connect this to Slack" or "add dagrun for our tests".

The quickstart walks through one recorded run. The setup skill is the procedure itself.

Engineering

How it is built

Quickstart: self-documenting CLIs

Every tool carries its own quickstart, user guide and --help, so you and your agents read the same instructions as the installed version. The agent skills point to them instead of copying them.

Tool documentation Skills

Two editions, one contract

Tools with Python and Rust editions share core commands. Differential tests run both on the same inputs and compare output, exit codes and state.

What is compared Editions

One validation graph

Every check is one dagrun graph under CPU and memory limits. make validate runs only what a change can affect, and a check the host cannot run is reported as skipped, never as passed.

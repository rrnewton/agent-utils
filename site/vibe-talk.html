Optional tool

vibe-talk

optionalearlyRust servicev0.0.1

A small Rust web server and phone web app for reading, discussing and replying to your coding agents' chat messages when you are away from the terminal: one-sentence summaries of long messages, named threads, replies from the phone, read-aloud and voice conversation.

About the clips on this page

Five short clips of vibe-talk in use: summaries, one report in full, new messages as they arrive, a reply from the phone, and threads on a desktop. Nothing on this page moves until you press Play the clip.

Purpose

What it is for

Problem
A team of agents posts long reports, often many before you look, and some of them wait on your answer. On a phone, and especially by ear, you need one line per long message, a way to open one particular message in full, threads you can find again, and a way to reply without a terminal.
What you get
A phone web app with Main, Threads and All views of a channel. One-sentence summaries of long messages and short, stable names for threads. Agent reports drawn the way the chat service draws them, with the agent's tag and title lifted into the row header. Replies and thread posts from the phone, and new messages while the page is open. Read-aloud through the phone's own speech engine or ElevenLabs, and voice conversation with an agent that looks messages up through vibe-talk's MCP endpoint.
Needs
A host to run it, as a native build or a container. Something in front of it that terminates TLS if you expose it; the microphone needs HTTPS. A credential for your chat service. Optionally a model provider for summaries and a voice vendor for conversation. It holds the chat credential, needs no access to any development workspace, and is deliberately not run next to the coding agents.
Where it fits
It is an optional phone front end for a chat service, beside the harness's owner channel rather than part of it. It reads and posts in the chat; it does not start, stop or type into agents. It reaches a harness's coordinator when agentctl chat bridges the same chat space: Google Chat through a compatible bridge, or Discord and Slack directly.

Summaries of long messages

A channel on a phone. Long agent messages are folded to their first three lines. Tapping Summaries replaces each folded message with a tinted, labeled one-sentence summary, and the view scrolls through the day's plan, a test fix, a feature report and an approval request.

Summaries are kept, so reopening a channel is instant. The full message stays one tap away.

One message in full

A worker's report on a CSV export feature starts as its one-sentence summary and opens with a tap. The server renders the message's markup: bold headings, bullets, a results table, a numbered list and labeled links. The agent's [worker-2] tag and its title sit in the row header.

New messages while you watch

With the newest messages on screen, worker-1 reports a regression test, and six seconds later the coordinator returns that worker's slot to the pool. Both appear without a reload, through vibe-talk's live stream, and a new chip jumps to them.

New messages arrive through vibe-talk's live stream, so the channel stays current while you watch it.

Answer from your phone

The owner taps Reply on worker-3's request to land a toolchain bump, types "Yes, land it. Thanks!" and sends. The reply appears linked to the request, which is marked as dealt with. Worker-3's "Landed" message arrives pointing back at the reply, and then the coordinator confirms that the day's tasks are done.

Threads on a desktop

At desktop width the page can show two columns: Main on the left and, on the right, the threads as cards, each with a generated name, a one-sentence summary, its age and its unread count. Opening csv-export-review shows that thread. The owner replies from the box beside it, and worker-2's answer arrives in the same thread.

A thread's name is chosen once and kept, so you can find it under the name you first learned. Its summary is refreshed as the thread grows.

Providers

Providers

vibe-talk is early, at version 0.0.1. Status: what works, what is stubbed in the README has the detail.

What vibe-talk supports
PieceSupported
DiscordDirectly, through Discord's HTTP API with a dedicated bot.
Google ChatThrough a compatible HTTP bridge that speaks Discord's API.
SlackBuilt in, through the Slack Web API.
Summaries and thread namesThe Anthropic Messages API, Google Vertex, or a compatible gateway.
Summaries from ElevenLabs insteadWith no model provider configured, the ElevenLabs conversational agent writes them.
Read-aloudThe phone's own speech engine, or ElevenLabs.
Voice conversationElevenLabs by default, or a WebSocket provider that your deployment runs.
TLSTerminate it in front of the server, or do not expose the server at all.

Try it

Running it yourself

vibe-talk's quickstart has six steps with exact commands: a Discord bot, the server's two tokens, a build, an optional step that puts it on the internet, an ElevenLabs agent, and a first conversation. It budgets about an hour for all six, and half that if you stop once the server runs.

Related work

vibe-talk's related-work comparison looks at hosted products and open-source projects for reaching coding agents by phone and voice. It recommended composing hosted products. The README states the decision plainly: a server is needed either way to hold the chat credential, and this project would rather own that front door than hand it to a vendor.
